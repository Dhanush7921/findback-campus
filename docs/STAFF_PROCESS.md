# Staff review & release process

1. **Register** every handed-in item (*Register found item*): public description (generic), **private verification details** (contents, serial numbers, names inside — never shown to students), photos, storage location.
2. **Review matches** (*Matching & review* or the item page). Scores are only hints. Propose a match when it is plausible; the student sees the generic description only.
3. **Claim**: the student or verified-phone guest submits ownership evidence from their portal → status *Ownership Verification*.
4. **Verify** (*Claim verification*): compare the claim evidence and the original complaint evidence with the private details. Approval requires confirming all three checks: evidence matches, features match, no conflicting claim. Reject with a reason if unsure — the student can be re-matched.
5. **Receiver confirmation** (*Handovers*): issue the short-lived, single-use receiver code. The receiver enters it from a verified-phone session and accepts the acknowledgement. For a proxy, record the owner's authorisation.
6. **Physical release**: check the receiver's physical ID, confirm the receiver details and complete the handover. If *Require a different staff member* is on, someone other than the approver must complete release.
7. Complaint → *Returned* and later *Closed*; item → *Returned*. All steps are in the activity log.

**Legacy PIN recovery**: applies only to pre-V2 complaints. Handle it in person after checking the college ID and recording the verification method.
